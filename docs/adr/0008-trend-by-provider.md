# ADR-0008: 趋势柱按 provider 分段

- 状态: 已接受(2026-07-30)

## 背景与问题

趋势图原为单色柱,只答"当日总量",答不出"这些量来自谁"。需要在柱内分段呈现构成,分段维度有三种候选,选错会带来配色抖动或语义错位。

## 备选项

1. **按 provider(模型提供方)分段**:provider 由模型名推断(claude-*→Anthropic;gpt-/o1-/o3-/codex-*→OpenAI;gemini-*→Google;其余→其他),顺序固定 Anthropic→OpenAI→Google→其他
2. 按模型分段——否决:本机实测 9 个模型、量级跨 5 个数量级(3072M ~ 11k),直接堆叠出现 1px 不可见薄段,需引入「Top N + 其他」合并规则;模型增减导致图例与配色抖动;"当天哪个模型在烧"已由「按模型拆分」条形图回答
3. 按 agent 侧(Claude Code / Codex)分段——否决:侧是工具、provider 是模型提供方,当前恰好一一对应但语义不同;将来某 agent 混用别家模型时,按侧分段会把不同 provider 的量混在一段里
4. 不分段(维持单色)——否决:不满足需求

## 决策

选定**方案 1**。柱高 = 当日总量,段高 = 该 provider 当日占比;段顺序与图例顺序固定(不随当日数据抖动),图例只列窗口内真实出现过的 provider。单侧筛选模式下退化为单段。provider 推断集中在 `shared/provider.ts` 一处。

## 后果

- 正面:与 agent 侧解耦——将来 agent 接别家模型无需改图表逻辑;段数稳定在 1–4,不会出现不可见薄段;配色固定可记忆
- 负面:同一 provider 内的模型构成看不出来(由「按模型拆分」条形图承担)
- 中性:provider 推断是模型名的启发式匹配,新厂商需在 `shared/provider.ts` 增补规则,否则落入「其他」

## 来源

用户 review 三个方案后的裁定(2026-07-30);本机实测的模型量级分布:9 个模型跨 5 个数量级(claude-opus-4-8 3072M ~ gpt-5.2-codex 11k),这是"按模型分段会出现不可见薄段"的依据。
