# Token 统计

> 关联: [features](../features/token-stats.md) · ADR-0005(对齐 ccusage,取代 0003) · ADR-0006(Codex 口径) · ADR-0007(用量归档) · ADR-0008(provider 分段) · ADR-0009(x 轴数据日)
> 补建说明:本篇为 2026-08-01 spec 转持久产物后**逆向补建**——边界条目从既有测试用例反推(口径决策见各 ADR,此处不复述)。

## Problem Statement

"哪个项目在烧我的额度、最近在烧什么"没有现成答案:两侧会话记录格式不同、口径不同,且 Claude Code 会自动清理旧会话文件——历史看着看着就没了。

## Solution

把两侧会话记录聚合成项目级与全局级两个视图,口径对齐 ccusage 可对账;每次刷新把当日聚合留档,源文件被清理后历史趋势仍在。

## User Stories

1. As a 用户, I want 项目概览默认显示累计总量、近 30 天趋势、按模型拆分与会话列表, so that 进入项目第一眼就知道它烧了多少、烧在哪。
2. As a 用户, I want 趋势柱按 provider 分段并可切单侧视图, so that 我看得出额度花在哪家模型上。
3. As a 用户, I want 日期轴只标有用量的日子且不重叠不越界, so that 窗口任意宽度下轴都可读。
4. As a 用户, I want 跨项目的全局趋势与模型拆分, so that 我能横向比较项目。
5. As a 用户, I want 源会话被 agent 清理后历史趋势仍在并有标注, so that 长期趋势不因清理而断档。
6. As a 用户, I want 数字与 ccusage 可对账, so that 我信得过这些数。

## 失败模式与边界

**序列 A:Claude 侧聚合**
- A1 总量四项全加(input/output/cacheRead/cacheWrite),cache 分列展示;模型桶同口径。
- A2 全树扫描:未注册项目的编码目录也计入全局(不依赖注册表),但不单列成项目。
- A3 同 `message.id + requestId` 重复行只计一次,保留 usage 更全的一条。
- A4 sidechain 重放(同 message.id、新 requestId)跨文件去重,保留非 sidechain 的一条。
- A5 无 `message.id` 的行不去重,照常累加。
- A6 synthetic 模型:token 计入总量,但不进模型桶。
- A7 `cache_creation` 明细优先:存在 ephemeral 明细时取 5m+1h 之和,不用扁平字段。
- A8 坏行跳过,不因单行损坏丢弃整个文件。

**序列 B:Codex 侧聚合**
- B1 逐轮 `last_token_usage` 增量累加;input 净化(减去 cached)、cached 单列;模型取 turn_context。
- B2 跨天会话按事件时间戳分摊到各自日期(不整会话堆在首日)。
- B3 subagent 会话 token 计入统计,但不进会话列表。
- B4 标题经 session_index 取得。

**序列 C:缓存与归档**
- C1 旧格式缓存(结构变更后的历史文件)不崩,按新结构重算——**结构定义与版本号是同一次改动的两半**(见 postmortems/cache-version-crash)。
- C2 缓存内容是垃圾时不崩,全量重算。
- C3 二次 build 结果一致(幂等);缓存文件为合法 JSON 且原子落盘。
- C4 首次合并即落盘归档;重开实例读得回。
- C5 源文件仍在的天:实时值**覆盖**归档(口径修正能自动纠正历史)。
- C6 源文件已消失的天:归档值保留,不被本次空扫描抹掉。
- C7 同一天内按 侧×项目×模型 分行,互不覆盖。
- C8 归档写入原子化,目录内无临时文件残留;归档文件损坏 → 降级为空不崩(下次扫描重新攒)。
- C9 归档覆盖的天集合可查(UI 据此画斜纹并附说明)。

**序列 D:趋势与轴渲染**
- D1 固定产出 30 根柱,按日期升序,末根为锚点当天;窗口外的历史天不进柱。
- D2 合计模式按 provider 分段,顺序固定(Anthropic→OpenAI→…),段值之和 = 总量;零值不产生空段。
- D3 同一 agent 用了多家 provider 时按 provider 拆,不按 agent 侧。
- D4 单侧模式只算该侧,段退化为单段。
- D5 无数据的天:总量 0、无段。
- D6 x 轴只标数据日(当前视图下有量的日子):首个与月份变化处 M/D,其余只标日;视图切换时数据日集合跟着变(同一天 0/正 两次调用,标签相应消失/出现)。
- D7 放不下时相邻成簇隔一丢弃(丢冲突对的右侧),存活标签仍钉柱中心;首末标签在容器内 clamp;月界标签被丢弃后新月份的下一个存活标签升回 M/D。
- D8 极端窄窗:持续简略但至少剩 1 个,不重叠不越界且算法终止。
- D9 全无数据 → 零标签。

**序列 E:快照自动保鲜(2026-08-08 定案,修「当天统计缺失」——此前重扫仅有启动与手动 ↻ 两个触发点,挂夜后 scannedAt 停旧、当天数据不展示)**
- E1 触发:窗口聚焦(距上次成功扫描 ≥ 节流窗才触发,默认 60s,防抖)+ 定时兜底(默认 5 分钟);手动 ↻ 语义不变。
- E2 并发:自动与手动共用同一扫描入口,in-flight 去重(同一时刻至多一次扫描在跑)。
- E3 自动触发的扫描失败 → **静默保留现有快照**,不打断用户、不清空数据,等下一个触发点;手动 ↻ 的失败仍显式抛给调用方。
- E4 新快照经既有推送链路下发;打开中的项目详情**换血式更新**(不闪"读取中"、分栏本地态保留——行为条目见 project-detail spec)。
- E5 节流窗与兜底间隔经环境注入(测试 seam;生产取默认值)。
- E6 跨天场景是 E1 的推论:挂夜后聚焦或兜底触发重扫,scannedAt 锚点前移,当天数据与轴随 D1 语义恢复,无需特判"跨天"。

## Implementation Decisions

- **口径**:见 ADR-0005/0006(两侧总量公式不同,不可互抄)。
- **归档**:见 ADR-0007(抗 agent 自动清理;实时值覆盖归档使口径修正可回溯)。
- **分段与轴**:见 ADR-0008/0009。
- **缓存**:按文件签名增量;**结构变更必须同步升版本号**,且同版本内加形状校验(损坏/漂移条目当未命中重算)。
- **自动保鲜**:触发层全在主进程(聚焦 + 定时,参数环境注入);渲染层零新链路(复用既有快照推送);重扫成本由增量缓存吸收。

## Testing Decisions

沿用 ADR-0002 双 seam:providers 层 fixture 单测覆盖两侧解析口径、去重、缓存与归档;纯函数(trend/axis/provider)单独单测覆盖分段与轴布局的几何约束;e2e 覆盖旧格式缓存启动不崩与趋势图渲染的几何检验(标签不重叠/提示不被裁剪)。对账基线:ccusage 逐日比对测试。自动保鲜(序列 E):聚焦节流判定为纯函数单测;e2e 经短间隔注入驱动全链路——追加会话数据后不手动刷新自动出现,且打开中的详情分栏本地态保留;聚焦事件在隐藏窗口测试体制下语义不可靠(既有 e2e 头注说明),聚焦触发路径与定时共用扫描入口,不单独 e2e。

## Out of Scope

- Codex 侧按模型的精确拆分(现为"会话主模型"级近似)。
- 首次运行本应用之前、且已被 agent 清理的会话(无法找回)。
