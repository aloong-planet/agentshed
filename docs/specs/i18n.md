# 界面多语言(i18n)

> 关联: [features](../features/i18n.md) · ADR-0013(语言集与范围边界) · ADR-0014(自建 typed i18n 层) · ADR-0015(结构化 IPC 错误)

## Problem Statement

界面文案全部以简体中文硬编码在源码里,非中文用户打开 app 后无法读懂任何一处标题、按钮、空态与错误提示。文案散落在渲染层的 JSX、主进程抛出的错误、以及手写的日期与数字格式化里,没有任何一层是可替换的。

## Solution

支持六种界面语言,外加「跟随系统」这一**默认选项**。用户可在设置页随时切换,切换即时对整个 app 生效、无需重启或保存。

「跟随系统」是**策略而非快照**:选中它时界面随 macOS 偏好语言变化,系统语言不在支持范围内时用英文;选定某个具体语言则等于锁定,此后系统语言怎么改都不再影响界面,直到用户主动选回「跟随系统」。

跨进程传递的失败信息改为不含自然语言的结构化形式,由渲染层按当前语言渲染措辞。

## User Stories

1. As a 法语用户, I want 打开 app 时界面自动就是法语, so that 我不必先看懂一门外语才能找到语言设置。
2. As a 用户系统语言为韩语的人, I want 界面回退到英文而不是中文, so that 我至少能读懂一门国际通用语言。
3. As a 中文用户在英文系统上, I want 能手动把界面切回中文, so that 系统语言不绑架我的应用语言。
4. As a 任一语言用户, I want 在设置页一眼看到所有可选语言、且每种都以它自己的文字书写, so that 即便当前界面是我看不懂的语言,我也能认出自己的母语。
5. As a 用户, I want 语言旁边同时标出该语言的英文名, so that 母语文字我不认识时(如误切到日语后想找回英文)仍有第二条线索。
6. As a 用户, I want 切换语言后整个界面立刻改变,包括侧边栏悬停提示与应用菜单, so that 不留下"一半翻了一半没翻"的夹生状态。
7. As a 键盘用户, I want 用 Tab 聚焦、方向键选择、回车确认、Esc 取消来完成语言切换, so that 不必依赖鼠标。
8. As a 用户, I want 语言选择在我下次打开 app 时仍然保留, so that 不用每次重设。
9. As a 用户, I want 操作失败时的提示也是我的语言, so that 最需要看懂的时刻不会突然冒出外文。
10. As a 用户, I want 日期、时间、数字按我的语言习惯显示, so that 不会看到中文界面里的美式日期或俄文界面里的中文星期。
11. As a 经常切换系统语言的人, I want 选中「跟随系统」后界面自动跟着系统走, so that 不必在每次改系统语言后再来 app 里改一遍。
12. As a 固定用某种语言的人, I want 选定具体语言后系统语言再怎么变都不影响 app, so that 我的选择不会被系统设置悄悄推翻。
13. As a 用户, I want 在选「跟随系统」时就能看到它当前解析成了哪种语言, so that 我不必靠猜来理解这个选项的实际效果。
14. As a 已经选了具体语言的人, I want 能重新选回「跟随系统」, so that 这个决定是可逆的,而不是选走了就回不去。
15. As a 开发者, I want 漏译在编译期就报错, so that 不会等到用户切到某语言才发现界面一片空白。
16. As a 开发者, I want 新增一条文案时六种语言都被强制补齐, so that 不存在"先上线再补翻译"的窗口。

## 失败模式与边界

### 启动与语言决定

语言偏好取值域是 `跟随系统 | zh | en | fr | es | ru | ja`,默认 `跟随系统`。下表中"解析"仅在偏好为「跟随系统」时发生。

| 场景 | 预期行为 |
|---|---|
| 首次启动(偏好为跟随系统),系统偏好语言列表首项是受支持语言 | 用该语言 |
| 首项不受支持但列表后续项受支持(如 `[ko, fr, en]`) | 按列表顺序取**第一个受支持的**,即法语。**不因首项不中就直接回退英文** —— 这是本节最易写错的一条 |
| 列表内无任何受支持语言(如 `[ko]`) | 英文 |
| 系统返回带地区或脚本的标签(`zh-Hans-CN`、`fr-CA`、`pt-BR`) | 按主语言子标签匹配:`zh-Hans-CN`→中文、`fr-CA`→法文;`pt-BR` 无匹配则继续看列表下一项 |
| 系统语言 API 返回空数组或抛错 | 英文,不崩溃 |
| 偏好为某具体语言,系统语言与之不同 | 用偏好的语言。系统语言**完全不参与**解析 |
| 偏好文件里 language 字段是非法值 / 类型错误 / 已被手工删除 | 降级为「跟随系统」(即默认值),走解析路径;其余偏好(外观方案与外观模式)不受影响 |
| 偏好文件整体损坏无法解析 | 全部偏好回默认,语言即「跟随系统」。与现有外观方案的降级行为一致 |
| 偏好读取完成前的首帧 | 不得先渲染默认语言再跳变(FOUC)。语言必须在首帧之前确定 |

### 跟随系统的动态性

| 场景 | 预期行为 |
|---|---|
| 偏好为「跟随系统」,用户在 app 运行期间改了 macOS 偏好语言 | 界面应随之改变。若做不到实时,至少下次启动生效,且不得停留在旧语言的错误状态 |
| 偏好为具体语言,用户改了 macOS 偏好语言 | 界面**不变**。已实测覆盖全部系统语言档位 |
| 从具体语言切回「跟随系统」 | 立即按当前系统语言重新解析并生效,不保留此前锁定的语言 |
| 偏好为「跟随系统」,系统语言从受支持变为不受支持 | 回退英文,不停留在上一次解析出的语言 |
| 界面语言与外观模式两个「跟随系统」并存 | 互不干扰:改系统语言只影响语言,改系统外观只影响明暗。两者是同构但独立的偏好,见 [appearance](appearance.md) 序列 B |

### 切换语言

| 场景 | 预期行为 |
|---|---|
| 切换到当前已选项(含重复选「跟随系统」) | 空操作,不弹提示 |
| 选中「跟随系统」时的提示措辞 | 需说明当前解析结果("已设为跟随系统 · 当前为 X"),不能只说"已切换为跟随系统"——用户看不出那是哪种语言 |
| 切换语言时正有异步扫描/加载在途 | 在途操作不中断;其完成后的提示用**新**语言 |
| 切换语言时某个错误提示正在显示 | 该提示按新语言重新渲染(错误以码+参数持有,不是已成句的字符串) |
| 语言写入偏好文件失败(磁盘满、只读) | 界面语言仍然切换(乐观更新),另给出失败提示说明"本次有效、重启后恢复"。与现有外观方案切换失败的处理一致 |
| 连续快速切换多次 | 以最后一次为准,不出现中间语言残留 |

### 下拉选择器

| 场景 | 预期行为 |
|---|---|
| 设置页可滚动,浮层展开后滚动页面 | 浮层关闭(浮层脱离滚动容器定位,不允许出现悬空错位) |
| 触发器位于视口底部、下方空间不足 | 浮层向上展开,不被视口裁切 |
| 浮层展开时点击页面其他位置 | 关闭,不选中任何项 |
| 浮层展开时按 Esc | 关闭且不改变语言,焦点回到触发器 |
| 键盘打开浮层(↓ 或回车) | 高亮**停在当前选中项**,不因"打开"这一次按键额外移动一格 |
| 方向键移动到首/末项后继续按 | 在**七**项(跟随系统 + 六语)间循环到另一端。分隔线不占位、不可聚焦 |
| 「跟随系统」项的次要文字 | 显示当前解析出的语言名,随系统语言变化而更新;不是静态文案 |
| 用键盘高亮某项但未按回车即关闭 | 语言不变(高亮不等于选中) |
| 窗口尺寸改变时浮层处于展开态 | 重新定位到触发器,不留在原坐标 |

### 文案本身

| 场景 | 预期行为 |
|---|---|
| 某语言缺少某条文案 | 编译期即失败,不进入运行期 |
| 运行期仍取不到文案(理论上不可达) | 回退英文并告警,不渲染空白、不显示 key 名 |
| 俄语等有多种复数形式的语言下显示数量 | 按该语言复数规则选词,不做"数字 + 固定量词"拼接 |
| 数量为 0 | 各语言按自身规则处理(英语用复数、法语用单数),不特判 |
| 长文案语言(法/俄正文最长,日语标签最长)下的固定宽度容器 | 不截断、不溢出;定宽容器需复核,已知风险点是插件行名与侧栏 |
| 界面语言与内容语言不一致(法语界面下浏览中文会话) | 内容按原文显示,不翻译;仅界面外壳随语言变 |

### 数字与时间格式

| 场景 | 预期行为 |
|---|---|
| 相对时间(今天/昨天/N 天前) | 按当前语言表达,不硬编码中文词 |
| 星期与月份名 | 按当前语言,不用硬编码中文数组 |
| 大数字分组符号(1,234 / 1 234 / 1.234) | 跟随当前语言,不写死单一 locale |
| 数值为 NaN / Infinity / 负数 | 不抛错、不显示 "NaN",给出稳定的降级表示 |
| 字节量与耗时单位 | 数值按语言格式化;单位符号(KB / MB / ms)不翻译 |

### 引入内容带来的能力

i18n 本身不新增内容渲染点,但它改变了既有渲染点的**内容来源**,需各自划界:

- **错误参数插值**:结构化错误的参数(路径、文件名、下标)来自文件系统与用户数据,拼进措辞时必须走与既有渲染同一套转义,不得因为"这是我们自己的错误文案"就绕过。
- **语言名的显示**:六种语言名是固定常量,不来自外部输入,不构成注入面。
- **应用菜单**:菜单项文案来自 i18n 字典(固定常量)。菜单是主进程原生控件,不接受渲染层传入的任意字符串。
- **既有内容渲染点(会话、记忆、产物)不在本次改动面**:它们渲染的是 agent 生成内容,其链接归宿与消毒边界已由既有不变量约束,i18n 不放宽也不收紧。

## Implementation Decisions

### i18n 层形状(见 ADR-0014)

- 简体中文为源语言、唯一真相。其余五语在类型上与源**逐条对齐**,少一条即 typecheck 失败。
- 源语言用 `as const` 会把值收窄为字面量类型,其余语言无法直接复用该类型;需要一个把叶子值放宽为 `string`、同时保留 key 集合完整性的类型映射。**该类型体操是 ADR-0014 处于「提议」态的原因**,实现期首先验证它,验证通过再升「已接受」。
- 带数量或插值的文案以**函数**承载(参数进、字符串出),不是模板串在调用处拼接。
- 复数调用平台内建 `Intl.PluralRules`,不自造规则表。
- 文案层是纯数据 + 纯函数,不依赖 React,主进程与渲染层共用。

### 语言偏好与生效语言(两个概念,不可合并)

- **语言偏好**是持久化的用户选择,取值 `跟随系统 | 六语之一`,默认「跟随系统」。
- **生效语言**是界面此刻实际使用的语言,恒为六语之一,由偏好推导:偏好是具体语言就取它,偏好是「跟随系统」就解析系统语言。
- 二者**不可合并成一个字段**。把解析结果直接存进偏好会让「跟随系统」退化成一次性快照——用户改了系统语言,app 却停在当初解析出的语言,且再也无法区分"他当初选了跟随系统"与"他当初手选了这个语言"。

### 语言解析

- 系统语言取 `app.getPreferredSystemLanguages()`(返回按优先级排序的**列表**)。**不用** `getLocale()` / `getSystemLocale()` —— Electron 43 的类型定义中这两者的文档均明确指出,取用户语言应使用前者;后两者描述的是区域格式(数字/日期/货币),与语言不是一回事。
- 匹配规则:遍历列表,对每项取主语言子标签与受支持集合比对,首个命中者胜出;全不中回退英文。**遍历整个列表**,不是只看首项。
- 解析是纯函数(语言列表 → 生效语言),与偏好存储解耦,便于把上述全部边界做成单测。
- 语言决定必须发生在窗口内容渲染之前,避免首帧语言跳变。

### 结构化错误(见 ADR-0015)

- 跨 IPC 的失败以错误码 + 参数传递,不含自然语言。错误码枚举与参数类型收在共享层,主进程与渲染层只从此处导入(沿用 ADR-0001 确立的单一类型源约定,三件套扩为四件)。
- **载体形态(2026-08-09 票 05 实测定案)**:码与参数**序列化进 Error 的 message**,带一个固定标记前缀;解码时按标记在串中定位载荷。两种更自然的写法都**不可行**——Electron 跨 IPC 回传时 Error 的自定义属性一律丢失(只剩 `message` / `stack`),故 `e.code = …` 到不了对岸;而 message 会被包一层 `Error invoking remote method '…': Error: …`,故 `JSON.parse(message)` 也解不出。解不出载荷时一律**退化为原样显示**(不抛),这既服务于迁移期新旧并存,也避免"报错时二次报错"。
- **错误参数只允许语言无关的取值**:标识符(通道名、字段名)、路径、数字。绝不放已成句的措辞——那正是本协议要消灭的东西。
- **未知错误码不透传**:解码时校验码在枚举内,不在则当旧式错误原样显示。透传会让渲染层取不到措辞而显示空白,空白比一句难看的原文更坏。
- **新增错误码必须配齐措辞,由 typecheck 保证**:码 → 措辞的分发写成 switch 且末尾带 `never` 断言,漏配即编译失败(已用变异实测:加一个未处理的码报 TS2345)。
- 基于错误语义的分支判断改为按错误码判定。**现存一处按中文子串匹配错误的分支必须一并改掉**,否则文案一变该分支静默失效且无测试会红。该处为 `SubagentsView.tsx` 的 `errLabel`(ADR-0015 原记作 `MemoryView.tsx:91`,文件名有误,已订正)。它读的是**数据字段**而非抛出的错误,故改法是给该字段配一个语言无关的失败类别(`errorKind`),分支按类别判;字段里原有的中文详情属数据字段展示文案,归票 07。
- **渲染层取当前语言走 context**(2026-08-09 票 05 落地):错误渲染点散布在会话页、插件列表、skill 展开块,逐层 prop 传要穿过与本事无关的中间组件;且 spec 要求正在显示的错误按新语言**重新渲染**,模块级变量改了不触发重渲染,做不到。故错误以码 + 参数持有,成句发生在渲染时。
- 契约校验层的失败原因同样纳入,不保留源语言原文。

### 偏好持久化

- 语言与外观方案同属 app 自有偏好,复用既有偏好存储与其原子写、三重降级策略。
- 持久化的是**偏好**(含 `跟随系统` 这个取值),不是解析出的生效语言。
- 既有偏好存储的接口是「一种偏好一个 setter」形状;新增语言需扩展该接口。
- 单条偏好非法只降级该条,不牵连其他偏好(沿用既有降级只准自伤的不变量)。

### 应用菜单

- 现无自定义菜单,走 Electron 默认菜单(按系统语言本地化)。本次新建自定义菜单,文案走 i18n、跟随 app 内语言。
- 结构照 macOS 标准菜单集;另接两个已有功能的快捷键入口(设置、全局刷新)。
- 语言切换后菜单需重建,不能只在启动时构造一次。

### 界面(结论,形态见下方原型门)

- 设置页新增「语言」分节,**置于「外观」之前** —— 它决定本页其余内容怎么读。
- 选择器形态为「标签 + 下拉触发器」,展开为浮层列表,共**七项**:首项「跟随系统」,一条分隔线,其后六种具体语言。分隔线表达的是两者性质不同——前者是策略,后者是取值。
- 每项左侧为主名(具体语言取其母语书写)、右侧为次要文字,当前项右端打勾并高亮。**「跟随系统」的次要文字位置放当前解析出的语言名**,与具体语言项放英文名的位置一致,让用户一眼看出这个选项此刻等于什么。
- 触发器在偏好为「跟随系统」时同时显示策略名与解析结果(主 + 次),偏好为具体语言时只显示该语言母语名。
- 浮层**必须脱离设置页的滚动容器**定位。已实测:设置页容器是 `overflow: auto`,同尺寸的普通绝对定位元素放进去会被裁切;浮层改用视口坐标系定位后四角与中心的命中测试全部通过。
- 浮层右缘与触发器右缘对齐,默认向下展开,下方空间不足时向上。
- 新增的下拉箭头与选中勾用**内联 SVG**(照抄 Lucide 官方内部元素),不用字符。存量字符图标不在本次改动面,已另票记录。
- 浮层投影需要新增一个主题变量,该变量必须在全部六个变量块(三配色 × 浅/深)各自赋值,深色下 alpha 需高于浅色才可见。

### 明确不改的既有形态

- `Provider` 与 `TrendMode` 两个类型曾以中文字面量作为运行时值(`'其他'`、`'合计'`),**已脱敏**为语言无关标识符(`other` / `total`)。**已核实这两个值从未被持久化**:用量归档的行结构只存模型原始串、token 计量缓存的条目同样只存模型原始串(provider 每次由模型名实时派生)、偏好文件里也没有它们。因此改名对既有用户数据零影响。
- **值与显示名分离**:脱敏后界面文字由与值同处一个模块的显示名常量表提供(形态与既有的外观方案标签表一致)。三家厂商名与 Claude / Codex 是各语言通用的专有名词,表中只有 `other` / `total` 两项需要随界面语言变化。
- **`byProvider` 的键类型偏弱是一处已知风险**:该字段以 `Record<string, …>` 承载 provider 键,产生端与消费端不一致时 **typecheck 不会报错**,趋势分段会静默变空(数值与柱高都正常,只是分段消失)。现行防线是产生端模块的警示注释与一条用产生端函数造键、经消费端读取的链路测试;收紧键类型以让类型系统接管这条一致性,已列入重构清单待定。
- 搜索框 placeholder 目前把图标字符与文案粘在同一字符串里,i18n 时须把图标拆出留在组件内,否则图标会被搬进六份语言字典。

## Testing Decisions

好测试只断言外部行为:给定语言与输入,文案层输出什么;给定系统语言列表,解析出哪种语言;给定错误码与参数,渲染成什么。不断言字典的内部结构,也不断言某个组件内部调用了哪个函数。

**Seam 选择**(优先复用既有,新增最少):

| Seam | 性质 | 覆盖 |
|---|---|---|
| 文案层(纯数据 + 纯函数) | **新增,本功能唯一新 seam** | 六语 key 完整性、复数规则、插值转义 |
| 语言解析(纯函数) | 新增,与上者同层 | 系统语言列表 → 生效语言的全部匹配与回退分支;偏好 + 系统列表 → 生效语言的推导(含"偏好为具体语言时系统列表完全不参与") |
| 偏好存储 | **既有** | 语言字段的读写、非法值降级 |
| IPC 契约校验 | **既有** | 结构化错误的形状 |
| e2e | **既有** | 锁定中文运行既有用例(断言零改动);另加 i18n 专项 |

**既有先例**:偏好存储与外观方案的现有测试不耦合任何文案,可直接照搬给语言;共享 UI 一致性检查脚本挂在验证网关上,是新增「文案完整性门禁」的现成样板。

**e2e 策略**(见 ADR-0013 决策背景):既有用例中约 127 处定位器与断言依赖中文文案,它们守的是**行为**而非文案,不因语言重写。做法是给测试预置偏好把语言钉死为中文——项目已有逐用例独立 userData 并预置文件的成熟手法。另新增专项用例覆盖:切换生效、六语均可加载、最长语言下关键布局不溢出。

**门禁**:新增一道检查,扫源码里是否还有未进字典的中文字面量,挂进验证网关。漏译由类型系统拦,漏抽由该门禁拦,两者不重叠。

**已知测试缺口(不造假的绿)**:Electron 应用菜单是 macOS 原生控件,Playwright 触及不到其渲染结果。可测的部分是**菜单模板构建**——它是「语言 → 菜单结构」的纯函数,按 seam 单测其文案与结构;菜单实际显示为哪种语言、切换后是否重建,只能人工验收。不得用"构建函数返回了法语文案"冒充"菜单显示为法语"。

## Out of Scope

- **阿拉伯语与 RTL 布局**:见 ADR-0013。本产品不承诺 RTL,CSS 保持物理属性、不改逻辑属性。
- **`docs/` 下的工程产物多语言**:specs / ADR / features / postmortems / ops 保持中文单语。仅 README 出六语。
- **应用名与窗口标题本地化**:Agentshed 作为品牌名各语不变。
- **存量字符图标 SVG 化**:17 种语义、约 33 个图标位,已另票记录,本次仅约束**新增**图标位守内联 SVG 规范。
- **agent 生成内容的翻译**:会话、记忆、产物按原文显示。
- **语言选择的更细粒度**:不区分地区变体(不做 zh-TW / en-GB / pt-BR),不做按项目或按视图的独立语言。
- **翻译外包与在线翻译平台对接**:文案以 TS 模块存放,不导出 JSON/PO 供外部译者编辑。
