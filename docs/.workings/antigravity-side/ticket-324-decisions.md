# Decisions — #324 Antigravity sessions and turns

Ticket: [#324](https://github.com/aloong-planet/agentshed/issues/324) · feature checklist: [checklist.md](checklist.md)

Decisions taken while implementing, under the owner's standing instruction to choose the reasonable option and record
it (2026-10-29). Where a decision is now part of a requirement's text, the spec says so; the rest live in the code's
comments and here. Those marked **(spec)** changed a requirement's, a failure mode's or an implementation decision's
wording and are listed for the owner's review.

| Decision | Chosen | Alternatives considered | Why |
|---|---|---|---|
| What the read allow-list holds for an Antigravity session | **(spec)** The listed conversation's database path — the session's identity, which every channel is given; the main process derives the transcript's path from the admitted database path (`sessionReadSource`) and reads the transcript only that way | The transcript path on the list, as session-view::REQ-004/AC-09 literally says; both paths on the list | The renderer names a session by its identity (the database) for the page, the turn, the freshness check and Finder; a transcript path on the list would let Finder be handed the transcript (US-001/AC-07 says never) and would admit a path no channel needs. Deriving the source from an admitted path keeps the exact-path allow-list fail-closed. Written back to REQ-004/AC-09 |
| Where a page's byte ranges come from | `sessionQuestions` returns a `source` (the session file, or the transcript); the IPC handlers take the source's identity before the index is consulted, as they always did, through `sessionReadSource` (a function of the path alone) | Return the source only from `sessionQuestions` and take the identity afterwards | Taking the identity after the index could let a transcript changed in between pass the end-of-read identity check with stale offsets |
| The page's byte figure (meta line) | The database's size — the record file Finder shows | The transcript's size | The meta line describes the record file; the confirmed prototype's figure (0.6 MB) is the size of the real fork's database. The fetch footnote still reports the transcript bytes actually read |
| The rewind rule's reading | **(spec, implementation decision)** A line is undone exactly when a later line's step index is not greater than its own; a line without a step index (never measured) is neither a redo nor undone | Only "from the first line carrying that index" | Equivalent whenever an earlier line carries the redo's index (every measured case); it also answers a redo whose index no earlier line carries (the transcript skips steps it does not write, measured: index 5 absent in `dispatch`) |
| A turn and a rewind inside it | The turn runs to the next kept question, less a trailing run of undone lines (a rewind back to a question); undone lines inside the turn stay in its range and the block assembler drops them by the same rule over the range | Cut the turn at the first undone line; split a turn into several ranges | A turn is one byte range (C2). Proven equivalent: an undone line inside a turn always has its redo inside the same range, so the range alone decides it |
| Counting a turn's calls | Over kept lines only | Over every line in the range | An undone call was undone (AC-07 counts what the turn holds) |
| A question's text | The request body, whitespace collapsed by the shared normaliser (session-view::REQ-002); the other harnesses' noise rules are not applied | `realUserText` as on Claude and Codex | None of those shapes is agy's; agy's own additions sit outside the request block. `normalize` is exported from session-title.ts so every side normalises by the one function |
| A request block without its closing tag | Listed whole (the whole content, normalised) | Take what follows the opening tag | Never measured; listed whole is the spec's do-not-lose rule for a line without a request block |
| A subagent that sends several messages in its dispatch's turn | **(spec, failure mode)** The return joins them in order, a blank line between | The first only; the last only | Nothing is lost; a later message in another turn renders nothing there (the spec's failure mode) |
| A system message's body | The text after `content=` in its `[Message]` line, up to `</SYSTEM_MESSAGE>`; the whole content when that shape is not found | Always the whole content | The measured shape; the fallback keeps an unexpected shape visible rather than empty |
| A result line with no call waiting | Renders nothing | An unknown trace | A known type; a call before the turn's range is not this turn's (never measured) |
| Tool block name and input | The call's `name`; the arguments as indented JSON; a dispatch's name its `TypeName` (else `invoke_subagent`), its prompt its `Prompt` (else the arguments) | Show `Role` as the name | `TypeName` is the subagent's type, as the prototype draws it (`subagent · self`) |
| A tool result's harness header (`Created At: … Completed At: …`) | Kept as written | Stripped | REQ-004/AC-04: the result line's text is the call's return; a stripping rule would rest on one shape |
| Titles | agy's summaries read once per build on the main thread (CON-002: in place when no log, through a copy with one); a read that fails while agy writes keeps the titles last read; read once on a page's first need when no build has run in this process | Read per conversation in the parse; keep the title in the per-file cache entry | agy titles a conversation after the fact, without the conversation's own files changing, so a cached title would go stale; one small read per scan |
| A summaries database that will not read in the title shape | **(spec)** Every title falls back to the first question | Report it | REQ-003/AC-03 ("cannot be read"); the summaries are an index agy rebuilds, not a usage source |
| Title key | The conversation's own id as its trajectory table records it | The database's name | The id the summaries and the copied steps use; equal to the name on every measured conversation |
| Last activity | The largest of every step's creation and completion times, copied steps included | Completion times only; own steps only | REQ-003/AC-04 says the largest step timestamp; copied steps are older by construction |
| The fork's parent | The readable conversation in the scan set whose own id is the source of the fork's last copied step; none when no such conversation (deleted, or unreadable) | Look for `<id>.db` on disk | The cache is the scan set: a parent deleted since the last scan leaves the banner at the next one (the spec's failure mode); an unreadable parent has no title or page to link |
| The fork pill's tooltip on an Antigravity row | **(spec)** "…the copied history has been stripped" — a copy variant of the existing pill | The Codex wording ("the replayed prefix") | The Codex wording is untrue of agy's copy; declared as the prototype exemption for a copy variant of a drawn control |
| The cache | `AntigravityFileAgg` gains `conversationId`, `subagent`, `listed`, `at`, `forkOf`, `title`, `questions`; `CACHE_VERSION` 18 → 19; **(spec)** the entry's signature adds the transcript's modification time and size | Keep the transcript out of the signature | C4: a transcript agy appended to must be indexed again, and agy writes both together while it runs |
| A conversation that cannot be read | No row, no page (`sessionParseFailed`), not on the allow-list, its transcript notwithstanding | List it from its transcript | token-stats::REQ-004/AC-01: "left out of every figure and every list" |
| A session page asked for a conversation whose cache entry is corrupt | Read again for that conversation alone (database and transcript), as the other sides' pages are | Refuse it | C4's single-file rebuild; the corrupt-entry case drives it |
| The measured transcripts as fixtures | Six real transcripts in `agy-transcript-fixture.ts`, paths substituted, after enumerating every transcript on the machine | Transcripts built from the spec | Fixtures independent of the spec (review-tests, dimension 1) |
| The summaries fixture | The real schema dumped from `conversation_summaries.db` (user version 3, WAL), the real titles | A minimal two-column table | The reader's shape check is exercised against the real table |
| The e2e journey | One launch: Sessions tab, a fork's page (banner, header copies and Finder, a turn), its parent, a gone source, global search | One case per criterion | The suite's rule: one launch per distinct fixture home |
