# Decisions — #322 Antigravity side: registry, project list and activity

Ticket: [#322](https://github.com/aloong-planet/agentshed/issues/322) · feature checklist: [checklist.md](checklist.md)

Decisions taken while implementing, under the owner's standing instruction to choose the reasonable option and record
it (2026-10-29). Where a decision is now part of a requirement's text, the spec says so; the rest live in the code's
comments and here.

| Decision | Chosen | Alternatives considered | Why |
|---|---|---|---|
| Where the side's data root is configured | `ScanRoots.antigravityHome` = `~/.gemini/antigravity-cli` | A `~/.gemini` root with subpaths derived from it | Only the CLI's own root is read in this ticket (token-stats::CON-001); later tickets add the configuration roots they read |
| Ledger entries that are not paths | Skipped; the other entries kept, no error | Treat the whole ledger as corrupt | CONTEXT's "degradation may only hurt itself": one bad entry must not empty the side |
| A `trustedWorkspaces` that is not a list | This side's error (`registryProjectsInvalid`), detected, no projects | Read as an empty ledger | The same split Grok makes: absent is A9 (normal), malformed is A3 (explained) |
| How the settings file is parsed | Strict JSON | A tolerant (comments, trailing commas) parse | agy writes the file itself as JSON; salvaging what agy might not read itself would be a false signal (CONTEXT, degraded judgements) |
| Which field names a conversation's folders | `workspace_uris` (field 7), else each workspace's folder (field 1.1) | Field 7 only; field 1 only | Both carried the same folder in all 19 real records; the fallback keeps a record without field 7 from silently leaving every figure |
| A first folder that is not a local `file:` URI | Credited to no folder | Skip to the next folder listed | The spec credits the first folder listed (token-stats::REQ-003/AC-08); substituting another would invent an attribution |
| What counts as "carries a nesting depth" | A non-zero depth | Any encoded depth, zero included | Zero is protobuf's absent value and no measured main conversation carries the field |
| How a conversation is read without writing (token-stats::CON-002) | No log: the `file:` URI with `immutable=1`, read-only. With a log: the log, then the database, copied into a `mkdtemp` directory of the system temporary directory, read there, removed in a `finally` | Database first; also copying `-shm`; a read-only open of the copy; a temporary directory in the app's user data | Log first leaves a whole database when agy exits between the two copies; the `-shm` is agy's live index and SQLite rebuilds one from the log (measured); a temporary directory is what the spec names |
| Copy-on-write clone for the copies | Plain copy | `COPYFILE_FICLONE` | Measured no clone through Node on this machine (400 MB: 767 ms with the flag, 698 ms without) |
| How the SQLite module is loaded | `process.getBuiltinModule('node:sqlite')` | Static import; `createRequire(import.meta.url)`; `better-sqlite3` | A static import fails under Vitest (Vite 5 resolves `sqlite` as a package); `createRequire` broke the CommonJS bundles of `bench:scan` and `restore:archive`; a native module would need an Electron rebuild |
| Re-reading conversations every scan | A memo of each conversation's folder and subagent flag, keyed by path, the database's mtime and the log's presence, mtime and size; successful reads only; only the conversations the last walk saw | No memo (open every database each scan); a memo by path alone | The spec's own key (token-stats Implementation Decisions); without it every rescan opens, and copies, every database |
| A conversation that cannot be read | Contributes nothing, raises no error, read again at the next scan | Keep its last successful result while a log is present | Counting unreadable conversations and keeping last results is token-stats::REQ-004, delivered with the usage reads (#323) |
| The empty conversation agy creates when its interface is opened | Credited like any other: moves its folder's time | Left out of activity | The spec's failure modes say it moves the time "as any session file's modification would" |
| The metadata row read | `trajectory_metadata_blob` where `id = 'main'` | Any row | The table's default id, and the only row in all 19 real databases |
| The format check on metadata reads | Not added here | Check `user_version` and the tables now | The ticket gives the format check on usage reads to #323 (token-stats::CON-001's split) |
| How the walk is shared | `SessionWalk` gains `antigravity`, walked once per scan for `scan()` and the token build | A read inside `scan()` alone | The existing rule (#160): one walk per scan, shared |
| The per-side Records typecheck forced open | `PROJECT_SKILLS_DIR` `.agents/skills`; global skills root `~/.gemini/antigravity-cli/skills`; trend primary provider Google; resume `agy --conversation <id>`; global skill `symlink`/`pkg` false/null | Partial Records; placeholder values | Each value is the spec's (the shared directory, agy's first global library, the side colour, session-view::US-001/AC-04); none is reached by a surface of this ticket |
| The trend chart's side switch | Not extended (no Antigravity mode yet) | Add the mode now | It is #323's ("its own line in the side switch"); a mode with no usage would show an empty chart |
| Surfaces that gain the side by construction | Shown now: the fourth side card, the Overview's per-side row, the Skills list's AG badge slot, the startup skeleton's card | Hold them back | They derive from the side Record (ADR-0020) and the confirmed prototypes draw them; zeros are what the side has until #323 and #325 |
| Hand-written side lists | `AGENT_SIDES` read off a `Record<AgentSide, true>`; the display data's skill-files check and the archive-restore script use it | Add the fourth name to each list | Typecheck now enumerates them (ADR-0020); a hand list is how the third side was once refused (#126) |
| A display cache saved before the side | Filled in on restore: not detected, zero totals, 0 per day, no symlink, no package; a present malformed entry still dropped | Drop it (as the contract would); bump the display format version | CONTEXT's page-switch invariant: a field added to a saved type is filled in on restore. Measured on this machine's cache: everything kept, against the snapshot, 515 statistics and 27 pages lost without it |
| The side's colours | `--ag-bg` / `--ag-fg` per appearance (#dde7fb/#3563b5, #1f2e49/#96b9f3); the dot on `--p-google` | A dot colour of its own | agents-overview::CON-004 and ADR-0021: the side colour is the provider colour, appearance-varying, not theme-varying |
| The "no side detected" empty state | `SIDE_ORDER.every(...)` | A fourth literal condition | A side added later joins by construction |
| e2e shape | One case walking every surface of the side in one launch; a colour case under the appearance launcher; the narrow-sidebar case measuring both long side names | One case per criterion | One launch per distinct fixture (the suite's rule); Antigravity is as long a name as Claude Code, so C5's width check must cover it |
| Fixtures | Real trajectory records (path replaced at the same length; the subagent's fields 4 and 10 dropped) and an encoder pinned to reproduce one byte for byte | Records built from the descriptors alone | Fixtures independent of the spec (review-tests, dimension 1) |
| Feature-page sentences the fourth side made false | Rewritten to name the sides whose data is read ("the Claude Code, Codex and Grok sides") | "Every side" with a footnote | Those pages describe what the product does now; the tickets that read Antigravity's usage, sessions and components rewrite them |
| CONTEXT's product line and chip list | Name Antigravity CLI and the ANTIGRAVITY chip now; the "being onboarded" note stays for the closeout | Leave CONTEXT for the closeout | The side is visible from this ticket on; the onboarding note is the closeout's to retire (its document sync row) |
