# Decisions — #323 Antigravity usage in the statistics

Ticket: [#323](https://github.com/aloong-planet/agentshed/issues/323) · feature checklist: [checklist.md](checklist.md)

Decisions taken while implementing, under the owner's standing instruction to choose the reasonable option and record
it (2026-10-29). Where a decision is now part of a requirement's text, the spec says so; the rest live in the code's
comments and here. The four marked **(spec)** changed a requirement's or a failure mode's wording and are listed for the owner's review.

| Decision | Chosen | Alternatives considered | Why |
|---|---|---|---|
| Which records give a call | All three agy writes — the step's usage, the generator record's usage, the retry entries — joined within a database by identity: the step brings the time, the generator record the model | Steps only; generator records only | token-stats::REQ-003/AC-01 names all three; steps carry the time, generator records the only model name (API-key steps carry no model info, measured); a generator record can outlive a pruned step, a step can carry a call no generator record names |
| Which duplicate across databases is kept | The first in scan order | The larger figures; the newest file | After the fork rule no measured identity is an own call of two databases; the same "first copy" rule Claude's deduplication uses |
| A call carrying no identity | Counted where it is; within its database joined to the unidentified call of the step its generator record names; never matched across databases | Dropped; matched by figures | AC-01's order has no fourth key; never observed (0 of 51); dropping would under-count with no trace |
| A retry entry with tokens but no identity | Not a call | Counted | AC-02 asks for "an identity different from the call it belongs to"; nothing shows it is another call |
| What marks a fork's copy | A step whose source cascade id names another conversation; a generator record whose named steps are all such steps, or **(spec)** which names no step present and whose own `custom_metadata.cascade_id` names another conversation | The step rule and the attached-record rule only; the trajectory id; identity matching alone | Measured on the fork (19 copied steps, 8 copied records naming the parent); the cascade id survives a rewind where the trajectory id changes; without the third rule a parent's record with no step would count for the fork once the parent is gone. Written back to token-stats::REQ-003/AC-06 |
| A conversation's own id | **(spec)** The trajectory table's `cascade_id` (a required column; no row = unreadable) | The database's file name | Equal on all 19, but a renamed file would make every step look copied and the conversation's usage vanish silently — the drop ADR-0037 rejects; read from the database, a drift is counted instead. Written back to token-stats::CON-001 |
| The format check | User version 1; `steps(idx, metadata)`, `gen_metadata(idx, data)`, `trajectory_metadata_blob(id, data)`, `trajectory_meta(cascade_id)`; a missing `main` trajectory record and an empty trajectory table are unreadable too | The version alone; failing lazily on a query | token-stats::CON-001: a drift shows as a counted conversation before anything is decoded |
| A field the reader reads arriving in another wire type | The record will not decode (unreadable) | Treat the field as absent | Absent would drop a call silently (REQ-004/AC-01) |
| `step_indices` encodings | Packed (as agy writes it) and unpacked | Packed only | Both are valid protobuf; three lines |
| When a failed read is agy writing | A log beside the database before or after the read, or the database gone | A log before the read only | AC-03 says before or after; a database deleted between the listing and the read is not a format change |
| A conversation deleted before its read starts | **(spec)** Left out of that scan: no signature, so no entry and nothing kept, and not unreadable; one deleted while it is read keeps its last result for that scan (the row above) | Keep its last result as for a deletion mid-read | Known gone before anything is read, and nothing suggests agy is writing it; keeping its figure would show the usage of a conversation just deleted for one more scan. The spec sentence "it leaves the figures at the next scan" was made exact after the post-implementation check drove both windows (F3) |
| What a failed read keeps | The last readable cache entry, under its old signature (read again next scan); an unreadable last entry is not kept, so nothing is counted | Keep any last entry | AC-03: "keeps its last successful result" and "not counted" |
| Unreadable verdicts | Cached under the conversation's signature and counted at every scan until the database or log changes | Re-read every scan | The spec's "not read again" key; a stable count |
| The activity walk | Applies the same format check; a read failing while a log is present keeps the last folder | Leave #322's walk as it was | REQ-004/AC-01 "every figure" includes the activity time; AC-03 kept consistent for the folder |
| Activity for a conversation whose usage record will not decode | Still gives its folder the database's time | Feed the usage read back into activity | Activity is the file's time by design (CONTEXT "Activity"); the walk runs before the build (#160). Written into the spec's failure modes |
| Where the reads run | On the parse workers, like the other sides' parses | The main thread | Generator records carry whole prompts; the pool already isolates a failing parse |
| Memory per record | Rows iterated one at a time; a record's bytes are in memory while it is read, its prompt never decoded | Read the generator table at once | Measured: 132 MB peak against 713 MB for thirty 20 MB records; the runtime's SQLite module has no incremental blob read. The spec sentence "never materialises them" corrected to this |
| A conversation changed while agy writes is read twice per scan | Accepted: once by the walk for its folder, once by the build for its usage | Make the walk read usage too; pass the engine's cache to the walk | The walk has no persisted cache (every launch would read all usage again on the main thread); stated in the spec's failure modes |
| The project key of a conversation | The merge key of its first folder whether or not the folder is registered; '' when the first folder is not local | '' for unregistered folders | The Codex and Grok rule; archive rows keep the folder, so they attribute once the folder is trusted |
| Where the unreadable count travels | `SideInfo.unreadable` on the snapshot, present only when not zero, set by the main process from the build, validated by both validators and saved with the display copy | A snapshot-level field; a field of the token statistics | ADR-0037's "structured notice on the Antigravity side"; sits beside the side's error; the notice is back before the first scan after a restart |
| The card's third line when the side also has an error | The error first (A3), then the unreadable count, then the counts | The count first | An error says the side's data is empty, which explains the figure more than a count. Written into agents-overview's failure modes |
| The tooltip | The line's native `title`, as the prototype draws it | The chart's floating tooltip | The confirmed prototype; the composition legend uses the same form for its hints |
| An Antigravity file asked for its session page | Refused as not indexed | Fall through to the Codex path | The side's session page is #324's; such a file is never on the read allow-list |
| The cache entry's shape | `{ kind, file, projectKey, unreadable, calls }`, each call a 7-tuple; no question index, title or time | Add #324's fields now | YAGNI; #324 bumps the version with its own shape. `CACHE_VERSION` 17 → 18 (ADR-0037's consequence) |
| The total against agy's own | **(spec)** The four fields summed; it exceeds agy's own by the cache reads and by any cache writes a call reports | Keep "by exactly the cache reads" | The case written for AC-03 showed the sentence holds only without cache writes (true of every measured call). Written back to REQ-003/AC-03 and noted on ADR-0037 (append-only) |
| Corrupt cache entries | The shape guard before any read of a cached entry's kind — in the new plan and session-page guard, and in the Codex resume check and fork-parent lookup | Fix only the new code; record the Codex sites | One defect class in one file: a corrupt entry failed the whole scan every time (upper escape). Failing-first cases for all four sites |
| The trend mode's label | `Antigravity` | `Antigravity CLI` | agents-overview::CON-004: the interface name |
| The unreadable line's copy | The prototype's: zh — the prototype's Chinese line and tooltip, as `zh.ts` holds them (`agents.unreadableConversations`, `agents.unreadableTip`); en "N conversation(s) couldn’t be read" (plural by the language's rules) / "agy may have changed its conversation format in an update; their usage is not counted" | — | The confirmed prototype (agents-overview::REQ-003/AC-02) |
| Fixtures | Four real usage records (an API-key and a signed-in call, step and generator record each, ids only) and encoders tied to them by what the reader reads off both | Records built from the descriptors alone | Fixtures independent of the spec (review-tests, dimension 1); the encoders write the measured field order |
| The e2e homes | Two launches: one covering the card's four windows, the unreadable line and its return, and a project Overview with two sides on one day; one for a corrupt settings file beside an unreadable conversation (the error before the count, the count after the repair — added after the post-implementation check, F5) | One case per criterion; the corrupt settings folded into the first launch | The suite's rule: one launch per distinct fixture. Folding the error in would put the first launch's first-render assertions behind a repair step |
