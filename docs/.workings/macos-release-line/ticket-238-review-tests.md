### False greens

- Red first: the reads, the state function and applying a view were each first red against a stub. That shows
  the behaviour missing, not that each case catches the fault it is there for, so every case was given a
  mutation of that fault instead.
- Mutations (`evidence/ticket-238/mutations-site-tests.txt`): on the final tree, 46 faults, each turning red
  exactly the cases it names, with the failure raised at an assertion that shows the mutated value or at the
  exception the fault causes; two controls (N19, M47) left everything green; each file restored byte for byte before the
  next, and the worktree's status the same before and after. Batch 1 (N1–N20, the first batch rerun, and N20 from
  the code review), batch 2 (M21–M47, one fault for each case no batch-1 mutation had turned red), N11b (N11 on
  its rewritten case) and L1–L2 (the list branch, rewritten in this ticket, under #237's list cases). Every one
  of the 72 cases in the four files has turned red under at least one of them.
- N18 survives, as predicted: a real draft has no publication date, so the date check refuses it too. M41 removes
  both checks and turns the draft case red. The draft check stays: GitHub gives drafts no date, but the rule is
  the draft flag.
- Found and fixed in this check: three cases that could not go red for the fault they named (increments above),
  each then shown to go red (M34, N11b, M46).
- The browser measurement, judged by the same question:
  - "The list state stays as served" asserts that nothing happens; the same run shows the script running (the
    other states change the page, and the list case records both reads).
  - The sideways-scroll check: nothing on the page root clips overflow; #237 showed it catches a 2000px element.
  - "Every button inside its card": below 760px the row's buttons wrap by design, so the check is decided by the
    wider widths, where they do not wrap.
  - The state is polled on the hero's button and every part is then read: all parts change in one synchronous
    call, so nothing lies between the polled and the read.
  - Colours are read with no transition on the pill, the note or the buttons.
  - Keeping the visitor's place: the positions reach both branches (a check of its own), and each half of the
    rule is shown to matter by a mutation that fails exactly the positions it gets wrong.
  - The time limit: the list state at 4s and the test state just after 5s bracket it.
  - No preflight: the same recording shows one for a control request.
  - The request search: all 21 files under `site/src` read, and a control string found.
- One slip of mine, caught: an edit the tool refused left a measurement running on unchanged code. The rebuilt
  script was checked for the new code before the result was read, which caught it; every rebuild since was
  checked the same way.

Conclusion: three weak cases fixed; no false green left that is known.
