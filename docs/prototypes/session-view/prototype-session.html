启动恢复各档在 app 里由这次启动的扫描进度与结果决定;app 内没有这个开关。

会话数据在 app 里由被打开的会话本身决定(fork 前缀能否确定剥离,取决于父会话文件是否在扫描集内);app 内没有这个开关。

取回状态在 app 里由取回前的一次签名校验(路径 + mtime + size)与该轮的读取结果决定:签名不符只重建该文件的索引,单轮读取失败只影响该轮、再点可重试;app 内没有这个开关。

打开来源在 app 里由会话是从哪里打开的决定:从全局搜索的命中直接打开的会话是「返回搜索结果」与「进入项目」两个出口;从项目里打开的、经「进入项目」之后再打开的、顺着 fork 横幅跳到的父会话,都只有返回项目;app 内没有这个开关。

搜索定位在 app 里由点进一条搜索命中触发(项目详情「会话」分栏的搜索,或全局搜索);app 内没有这个按钮。

项目目录在 app 里由扫描时项目路径是否还在决定;失效项目的会话只能从全局搜索打开,所以选「已不存在」会同时切到全局搜索来源;app 内没有这个开关。

会话 ID 在 app 里由会话记录本身决定:记录里没有 ID(本机全量枚举未见,这是兜底形态),或者页面是从更新前的存盘恢复的、首轮扫描还没刷新它,都是「读不到」;app 内没有这个开关。

项目路径在 app 里由项目所在目录决定,这里换成本机实测最长的项目路径看提示的折行;app 内没有这个开关。

外部操作的结果在 app 里由系统决定:记录文件在打开 Finder 时已被移动或删除、剪贴板拒绝写入;原型里点按钮不真的复制,也不真的打开 Finder;app 内没有这个开关。
